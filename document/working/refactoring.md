# 根本的に作り直し（現行方針）

## 目的

アプリケーション層以降を作り直し、責務分離と依存方向を明確化する。

- ドメイン: 計算ロジック
- アプリケーション: ユースケースの組み立て
- インフラ: 入出力・永続化
- プレゼンテーション: 実行インターフェース（CLI等）

依存方向は常に内側へ向ける。
具体的には、application は domain に依存し、infrastructure は application/domain のポートに依存し、
presentation は application に依存する。

## 現状

- `src/monocycle_nash/main.py` は再構築中のため未実装
- 旧CLI仕様（feature 実行や runmeta 運用）はアーカイブ文書側で参照可能

## 再構築の範囲

1. **application**
   - 行列構築・分析実行のワークフローをユースケースとして整理
   - 設定読込・分岐制御をドメインから切り離す
2. **infrastructure**
   - 入力読込と出力書込をポート実装として分離
   - 具体的な保存形式や保存先はアプリ層から独立して差し替え可能にする
3. **presentation**
   - CLI/実行入口をアプリ層呼び出し専用の薄い層として再設計
   - 実行引数・表示責務をここに限定する
